为什么我选择了纯静态网站

前阵子纠结要不要上框架：React？Next.js？Astro？翻了一圈，最后还是回到最朴素的那一套——纯静态的 HTML、CSS、JS。

简单，是一种奢侈

框架很强大，但强大往往意味着复杂。而很多时候，我们根本用不上那些复杂。

  • 没有 npm install 等半天的焦虑；
  • 没有版本升级把整个项目搞崩的风险；
  • 没有「构建失败」这种玄学问题。

它对「长期」友好

一个纯静态站点，十年后大概率还能打开。它不依赖任何会停服的服务，也不依赖某个特定版本的运行时。这种确定性，在「我想留点东西下来」这件事上，特别重要。

能跑十年的东西，比能跑十分钟但很酷的东西，更值得托付。

当然，它也有边界

纯静态不适合需要实时交互、用户登录、动态数据的场景。但对我这种「写写文章、记记想法」的需求来说，它刚好。

所以结论是：先想清楚自己要什么，再决定用什么。工具是为人服务的，不是反过来。
